# Полный список из 50 заведений для AI Marketplace Алматы

Ниже — очищенный список без технического placeholder `ALM-043B` и без дублирования ID. Это **каталог-ядро MVP**, сформированный по сигналам популярности, отзывов, туристической узнаваемости, разнообразия форматов и потенциальной пригодности для бронирования.

В качестве внешних сигналов использованы рейтинги и каталоги Restolife, Tripadvisor, Restoran.kz, Ultima Guide и локальные подборки баров. Restolife формирует рейтинг по данным 2GIS, Яндекс Карт, Google Maps и собственным оценкам, а Tripadvisor предоставляет отдельные сигналы по отзывам путешественников, кухням, ценам и популярности заведений. cite cite[^1][^2]

> Статус `candidate` означает, что заведение включено в каталог для дальнейшей карточной проверки. Это не означает, что каждое поле уже подтверждено по актуальному 2GIS или официальному меню.

## 8. Категории для следующей волны

После первых 50 заведений в marketplace стоит добавить:

- кофейни с рабочими местами;
- банкетные залы;
- event-площадки;
- конференц-залы;
- отели;
- коворкинги;
- караоке;
- детские центры;
- SPA;
- beauty-салоны;
- спортивные клубы;
- кейтеринг;
- rooftop-площадки;
- рестораны за пределами центра;
- halal-заведения;
- vegan и healthy food;
- заведения с панорамным видом;
- семейные рестораны с детской инфраструктурой.

Для кейтеринга уже существуют отдельные локальные категории: например, The Kitchen Catering предлагает выездное обслуживание банкетов, а TVN Catering работает со свадьбами, корпоративами, днями рождения и конференциями. Такие компании следует хранить не как обычные рестораны, а как отдельный тип `catering_provider`. cite cite[^6][^7]

## 9. Финальный статус списка

Этот список можно использовать как:

- первоначальный каталог для прототипа интерфейса;
- seed data для Supabase или Airtable;
- основу для AI matching;
- набор тестовых объектов для сценариев поиска;
- список для ручного outreach владельцам;
- shortlist для подключения онлайн-бронирования.

Но перед публичным запуском каждого объекта нужно проверить:

1. Фактическое существование и адрес.
2. Конкретный филиал.
3. Текущий номер телефона.
4. Рабочий Instagram или сайт.
5. Актуальное меню.
6. Средний чек.
7. График работы.
8. Наличие столиков и бронирования.
9. Депозит и минимальный заказ.
10. Парковку, Wi‑Fi, детей, животных и террасу.
11. Источник каждого значения.
12. Дату последней проверки.

Итоговый production-статус этих 50 объектов должен выглядеть примерно так:

```json
{
  "venue_id": "ALM-001",
  "name": "Nuala",
  "category": "restaurant",
  "verification_status": "partially_verified",
  "last_verified_at": "2026-08-08",
  "data_quality_note": "Состав включён в MVP shortlist; карточка требует полевой проверки филиала, меню, цен и бронирования"
}
```
