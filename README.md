# Мезгіл — MVP платформы подбора и бронирования заведений

Демонстрационный MVP по ТЗ: каталог заведений Алматы, поиск и фильтрация, детальные
страницы, бронирование, демо-оплата, кабинет пользователя, кабинет бизнеса и AI-подбор
на mock-логике.

## Запуск

```bash
npm install
```

```bash
npm run dev
```

Приложение поднимется на http://localhost:3000

Другие команды:

```bash
npm run build && npm start
```

```bash
npm run typecheck
```

## Архитектура

**Сущности** вынесены в `src/types` — по модулю на каждую: `User`, `Business`, `Venue`,
`Booking`, `Category`, `Service`, `Product`, `Review`, `AIRecommendation`, `Location`,
`Payment`, `Favorite`, `Search`/`Filters`. Поля подобраны так, чтобы 1-в-1 лечь на
колонки таблиц при переходе на Prisma.

**Поток данных** односторонний:

```
data/db.ts  →  server/repositories  →  RSC-страницы
                        ↑                    ↓
                 app/api/* (route handlers) ← клиентские компоненты (TanStack Query)
```

Страницы читают репозитории напрямую на сервере, клиентские компоненты — через
демо-API. Это значит, что при подключении настоящей БД меняется **только слой
репозиториев**.

**Состояние каталога живёт в URL.** Сервер разбирает query-параметры
(`lib/query-params.ts`), фильтрует и передаёт результат вниз пропсами; клиентские
компоненты только строят новый URL и делают `router.push`. Ссылку на любую выдачу
можно скопировать и открыть.

> Важно: в клиентских компонентах каталога намеренно **не** используется
> `useSearchParams()` — этот хук переводит поддерево в client-side rendering до
> ближайшей Suspense-границы, из-за чего страница зависала бы на скелетоне.

**Демо-данные детерминированы.** Генерация построена на seed-based ПСЧ
(`lib/utils.ts → createRandom`), поэтому сервер и клиент всегда видят одинаковые
данные. Точка отсчёта времени — `src/data/now.ts`: текущая дата, приведённая к
полудню, чтобы календарь бронирования не предлагал прошедшие даты, а отзывы и
уведомления выглядели свежими.

## Демо-данные

- **32 заведения** в 10 категориях с координатами, ценами, удобствами и расписанием
- **12 кухонь**, 9 районов Алматы
- **256 отзывов** (8 на заведение) с оценками по критериям, фото и ответами заведений
- меню (разделы и позиции), услуги, товары
- 13 бизнесов, брони за последние ~2 месяца и на 3 недели вперёд
- избранное, история поиска и уведомления демо-пользователя

Заведения и компании вымышлены.

### Фотографии

ТЗ предполагает фотографии-заглушки. Их отдаёт роут `GET /api/photo/{seed}/{w}/{h}` —
детерминированный SVG-градиент. Приложение не зависит от внешних CDN и работает офлайн.
Чтобы подключить реальные фото, достаточно заменить поле `url` в данных на ссылку CDN:
компоненты используют обычный `<img>`.

Аватары — `GET /api/avatar/{seed}/{size}` (инициалы на градиенте).

## Демо-API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/venues` | поиск по каталогу с фильтрами и сортировкой |
| GET | `/api/venues/{slug}` | карточка заведения со всем контентом |
| GET | `/api/catalog/meta` | справочники для панели фильтров |
| GET | `/api/search/suggestions` | подсказки строки поиска |
| GET | `/api/availability` | слоты на дату / ближайшие 14 дней |
| POST | `/api/bookings` | создание брони |
| GET/PATCH | `/api/bookings/{id}` | получение и смена статуса |
| POST | `/api/payments` | демо-оплата |
| GET/POST | `/api/favorites` | избранное |
| GET/POST | `/api/notifications` | уведомления |
| POST | `/api/ai/recommend` | AI-подбор |

Все ответы в едином конверте `{ ok: true, data }` / `{ ok: false, error }`
(`ApiResponse<T>` из `src/types`).

## AI-подбор

Реализован без LLM — прозрачным взвешенным скорингом (`src/server/ai/recommend.ts`):

1. Свободный текст разбирается по ключевым словам (`keywords.ts`) — кухня, бюджет,
   количество гостей, район, время, повод.
2. Каждое заведение получает баллы по факторам: кухня (+30), бюджет (+24), локация
   (+16), размер компании (+14), время работы (+12), рейтинг, акции, расстояние.
3. Жёсткие отсечения: не влезает компания, закрыто в нужное время, бюджет превышен
   более чем на 25%.
4. Результат нормализуется в процент совпадения, а каждый фактор возвращается с
   человекочитаемым объяснением — пользователь видит, **почему** место предложено.

Пример из ТЗ (итальянская кухня → до 10 000 ₸ → 8 человек → центр → вечером) даёт
Basilico с 96% и разбивкой по факторам.

Контракт `recommend(request) → AIRecommendationResult` совпадает с тем, что вернёт
вызов OpenAI со structured output: для перехода на реальную LLM заменяется только
реализация движка, интерфейс и API остаются прежними.

## Карта

Собственный рендерер (`components/map/venue-map.tsx`): координаты проецируются в
проценты контейнера (`lib/geo.ts`), поверх стилизованной подложки рисуются пины с
ценой, есть зум, перетаскивание и карточка выбранного заведения. Ключи и внешние SDK
не нужны.

Для перехода на Mapbox/Google Maps меняется только подложка и функция проекции —
логика пинов, синхронизация со списком и обработчики остаются.

## Подготовка к продакшену

| Что подключается | Где менять |
| --- | --- |
| PostgreSQL + Prisma | `src/server/repositories/*` — сигнатуры функций уже асинхронно-совместимы, `src/data/db.ts` удаляется |
| Аутентификация | `getCurrentUser()` / `getCurrentBusiness()` — заменить на сессию |
| Stripe | `src/server/repositories/payments.ts` — `PaymentBreakdown` уже совпадает с моделью PaymentIntent |
| OpenAI | `src/server/ai/recommend.ts` — заменить движок, оставив контракт |
| Реальные фото | заменить `url` в данных, удалить `/api/photo` |
| Карты | заменить подложку в `venue-map.tsx` |

  режимы «список» и «карта», пагинация
- Детальная страница: hero, галерея с полноэкранным просмотром, услуги, товары, меню,
  фотографии, отзывы с фильтрами и ответами, карта, контакты, часы работы, sticky-CTA

  контакты, валидация
- Демо-оплата: заказ, стоимость, комиссия, итого, заглушка «Эквайринг будет подключен
  позже»
- Кабинет пользователя: профиль, настройки, избранное, история поиска, история
  бронирований, рекомендации, уведомления, AI-советы
- Кабинет бизнеса: дашборд, объекты, редактор карточки, фотографии, меню, услуги,
  товары, расписание, брони, отзывы, аналитика (просмотры, доход, конверсия)
- Адаптивность: desktop / tablet / mobile, нижняя навигация на мобильных
- Тёмная и светлая тема, skeleton-загрузка, пустые состояния
